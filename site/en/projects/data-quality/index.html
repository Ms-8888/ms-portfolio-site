Projects / case study

Data quality tool

Cleaning customer lists without changing anything you haven't seen.

Python · openpyxl · argparse · optionally a local or hosted language model

Problem

Customer lists from forms and imports drift: "Acme NV", "ACME N.V." and "acme nv" are three companies in a report, a typo in an email domain makes a mailing bounce, the same person is in the list twice, and an age of 212 skews an average.

Cleaning by hand is slow. Cleaning automatically without asking rewrites data you may need.

What I built

  • A command-line tool with two commands: dq scan shows the problems and changes nothing, dq clean proposes fixes and asks for approval for each change.
  • Five checks: invalid emails (including known typos in the domain), variant spellings of company names, duplicate rows, missing required fields and suspicious numbers.
  • The result is a cleaned copy plus a change report with before and after, what you rejected and what a person has to review. The original file is never overwritten.
  • A language model (local or hosted) can help choose the right company name. The model only sees the spellings, never the rows, and may not invent a name: its answer has to resemble a spelling that really occurs.
  • Safety when writing: text that a spreadsheet program would run as a formula (for example a cell starting with =) is neutralised.

How it works

  1. Read fileCSV or Excel; rows with too many fields are rejected instead of truncated
  2. Five checksproblems with row number and reason
  3. Proposalsonly where a safe fix exists; company name via rules or model
  4. You approveyes, no, accept all or stop, per change
  5. Resultcleaned file and change report

Not yet
Not tested on real files. The sample data and the checks were written by the same person, so "16 of 16" shows the checks do what they promise, not that they are good on real data. Three company groups is very few. The API mode has not been tested yet.

What the independent review found. Four AI reviewers found problems I hadn't seen, and for most of them I first reproduced them with a failing test. The tool merged companies that don't belong together ("Vision 2000" and "Vision 2001", or chains of similar names), so approving a proposal could overwrite a real customer. Multi-line cells in a CSV were corrupted, and a row with an extra column silently lost that data. Phone numbers got an apostrophe in front of the number when written out. Those are fixed, each with a test. What I deliberately did not fix (finding outliers when almost all values are equal) is listed under "Limitations" in the README.
