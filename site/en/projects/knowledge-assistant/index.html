Projects / case study

Knowledge assistant

Answering questions from company documents, with sources, and admitting when the answer isn't there.

Python · FastAPI · PostgreSQL + pgvector · fastembed (ONNX) · React · nginx · Docker

Problem

Employees keep asking the same questions about holidays, expenses and IT rules, and the answers sit in handbooks nobody searches. Keyword search misses rephrasings ("leave days" versus "holiday days"). A chatbot that answers from memory invents policy.

What's needed: an answer that comes from the company's own documents, with the source next to it, and a clear refusal when the documents are silent.

What I built

  • Reading Markdown, PDF and DOCX files, splitting them into passages and storing them with a vector representation in PostgreSQL (pgvector).
  • The vectors are computed locally with a multilingual model (no key, no account), so search always works, even without a language model.
  • Three ways to give the answer: show only the most relevant passage, a local model (Ollama), or Claude. Every answer shows its sources with file, section and score.
  • An admin view with all questions asked, where unanswered and uncertain questions can be filtered, so the document owners see what's missing.
  • Security: no upload feature, limits on question length and request rate per visitor, admin key compared in constant time, a daily cap and kill switch for paid model calls, API container running as a non-root user.

How it works

  1. Read documentssplit by headings and length (max. 800 characters)
  2. Compute vectorslocally, 384 numbers per passage, stored in pgvector
  3. Ask a questionthe question gets the same vector representation
  4. Four most related passagesbelow a threshold of 0.28 the answer is "I don't know" straight away
  5. Answerwithout a model: the best passage; with a model: a short answer or "not found"
  6. Sources and logthe passages are shown; the question is stored for the admin view

Result

I wrote 38 test questions and had them checked automatically: is the right document on top, and does the answer contain the expected fact? I set the 0.28 threshold with a separate test of 10 questions, not with these 38.

What this says
Without a language model, "I don't know" only works for questions about a completely different topic. Questions on the right topic but without an answer scored 0.33 to 0.54, and three of the four scored higher than the lowest-scoring real question (0.42). So no threshold can separate them. That takes a model.
Not yet
The API mode with Claude has not been tested yet. Not tested with real company documents or under load. The test set is small and written by me, so this is a smoke test, not a benchmark.

The first measurement looked perfect and was wrong. The local model first scored 28 out of 28. When I read the raw answers, the model had written "Niet_gevonden" and "NIEGT_GEVONDEN" instead of the agreed word. My code only accepted the exact spelling, so those refusals reached the user as an ordinary answer. And my own check looked for the word "niet" (not), which is also in that refusal. I made the code recognise what a refusal is (with tests) and made the check stricter. The local result got worse (27 instead of 28) but more honest. The first run is still in the repo.

Then I had four independent AI reviewers review the project (security, claims, code quality, recruiter). They found real bugs, such as deleted documents that still produced answers and visitors behind nginx sharing one rate limit. For each bug I first wrote a failing test and then the fix. All nine problems I reproduced this way turned out to be real.
